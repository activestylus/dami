# Chapter 2: Models & Fields

## Defining Models

Models define your data structure and behavior:

```ruby
Dami.model :users do
  fields do
    field :name, :string
    field :email, :string
    field :created_at, :datetime
  end
end
```

Models are namespaced by table name. No classes, no inheritance - just clean configuration.

## Field Types

Dami supports all common SQL types:

```ruby
Dami.model :products do
  fields do
    field :name, :string          # VARCHAR/TEXT
    field :description, :text     # TEXT (longer)
    field :price, :decimal        # DECIMAL/REAL
    field :quantity, :integer     # INTEGER
    field :active, :boolean       # BOOLEAN (0/1)
    field :launched_at, :datetime # DATETIME
    field :metadata, :json        # JSON (stored as TEXT)
  end
end
```

**Type mapping:**
- `:string`, `:text` → TEXT
- `:integer`, `:boolean` → INTEGER  
- `:decimal`, `:float` → REAL
- `:datetime`, `:date`, `:time` → DATETIME
- `:json` → TEXT (auto-serialized)

## Virtual Fields

Virtual fields exist in your model but not in the database. Perfect for:
- Password confirmation
- Terms acceptance checkboxes
- Calculated values for validation
- Multi-step form data

```ruby
Dami.model :users do
  fields do
    field :email, :string
    field :password_hash, :string
  end
  
  virtual do
    field :password, :string
    field :password_confirmation, :string
  end
  
  validate do
    rule :password, :required, min_length: 8
    rule :password_confirmation, :required, matches: :password
  end
end

# Virtual fields are accepted as input
user = Dami.db(:users).create(
  email: 'alice@example.com',
  password: 'SecurePass123',
  password_confirmation: 'SecurePass123'
)

# But never saved to database
user[:password]  # => nil (not in database)
user[:password_hash]  # => actual hash value
```

**How it works:**
1. Virtual fields pass validation
2. Virtual fields pass protection checks
3. Before INSERT/UPDATE, virtual fields are filtered out
4. Only real fields touch the database

## Multiple Models

Define as many models as you need:

```ruby
Dami.model :users do
  fields do
    field :name, :string
    field :email, :string
  end
end

Dami.model :posts do
  fields do
    field :user_id, :integer
    field :title, :string
    field :body, :text
  end
end

Dami.model :comments do
  fields do
    field :post_id, :integer
    field :author_id, :integer
    field :content, :text
  end
end
```

Each model is independent and can be queried separately.

## Multiple Databases

Connect multiple databases and assign models to them:

```ruby
# Connect to two databases
Dami.connect(:default, adapter: :sqlite, path: 'app.db')
Dami.connect(:analytics, adapter: :sqlite, path: 'analytics.db')

# Assign models to databases
Dami.model :users do
  database :default  # Uses app.db
  
  fields do
    field :name, :string
  end
end

Dami.model :events do
  database :analytics  # Uses analytics.db
  
  fields do
    field :event_type, :string
    field :timestamp, :datetime
  end
end

# Queries automatically use the correct database
Dami.db(:users).create(name: 'Alice')    # → app.db
Dami.db(:events).create(event_type: 'click')  # → analytics.db
```

## Model Organization

**Small projects:** Define models inline

```ruby
# config/models.rb
Dami.model :users do
  fields { field :name, :string }
end

Dami.model :posts do
  fields { field :title, :string }
end
```

**Large projects:** One file per model

```ruby
# models/user.rb
Dami.model :users do
  fields do
    field :name, :string
    field :email, :string
  end
  
  validate do
    rule :email, :required, :email
  end
end

# models/post.rb
Dami.model :posts do
  fields do
    field :title, :string
    field :body, :text
  end
  
  validate do
    rule :title, :required
  end
end

# config/environment.rb
require_relative '../models/user'
require_relative '../models/post'
```

## Field Access

Access field values using hash syntax:

```ruby
user = Dami.db(:users).find(1)

user[:name]       # => "Alice"
user[:email]      # => "alice@example.com"
user[:created_at] # => Time object

# Convert to plain hash
hash = user.to_h
hash.class  # => Hash (not RecordProxy)
```

## Best Practices

**Keep models focused:**
```ruby
# Good: Clear, focused model
Dami.model :users do
  fields do
    field :email, :string
    field :name, :string
  end
end

# Avoid: Too many fields
Dami.model :users do
  fields do
    # 50+ fields...
  end
end
# Consider splitting into multiple models
```

**Use virtual fields for form data:**
```ruby
# Good: Virtual fields for non-persisted data
virtual do
  field :terms_accepted, :boolean
  field :current_password, :string
end

# Avoid: Storing temporary form data in database
fields do
  field :terms_accepted, :boolean  # Don't persist this
end
```

**Name fields consistently:**
```ruby
# Good: Consistent naming
field :user_id, :integer
field :created_at, :datetime
field :is_active, :boolean

# Avoid: Inconsistent naming
field :userId, :integer      # Use snake_case
field :creation_time, :datetime  # Use *_at convention
field :active, :boolean      # Use is_* for booleans
```

## Quick Reference

```ruby
# Basic model
Dami.model :table_name do
  fields do
    field :column_name, :type
  end
end

# With virtual fields
Dami.model :users do
  fields do
    field :email, :string
  end
  
  virtual do
    field :password, :string
  end
end

# Multiple databases
Dami.model :users do
  database :analytics
  fields do
    field :name, :string
  end
end

# Field types
:string, :text, :integer, :decimal, :boolean, :datetime, :json
```
